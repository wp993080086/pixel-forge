# 产品需求清单｜本地图片编辑工具

> 版本：**v0.2**（2026-11-02 可行性评审修订）
> 定位：**纯本地离线图片处理**，原图不上传服务器；多端部署：Windows / Android / HarmonyOS Next / Web，后续拓展微信小程序
> 核心规则：各端能力不一致，**功能按端做差异化阉割**；优先保障 PNG 透明通道保留；JPG 原生不支持透明，转换时界面提示用户
> 选型背景备忘：Flutter 为主基线，Web 为 Flutter Web，小程序单独适配、能力最弱
> **端优先级**：Windows（首发基线）→ **HarmonyOS Next（优先级高于 Android）** → Android → Web → 微信小程序
> **MVP 端范围（已拍板）**：Windows + HarmonyOS Next + Android **三端同步**；Web 分批接入（导出统一浏览器下载）、微信小程序延后至 V3+（附录 #7 / #10 / #11 已拍板）

## 一、支持图片格式（导入 / 导出分开，区分【导入支持】、【导出支持】）

> 说明：下面是通用全集；每个端单独维护一张兼容表，不支持的格式在对应端隐藏选项、置灰

### 导入（可打开预览、进入编辑）

- 位图类：JPEG（jpg/jpeg）、PNG、BMP、WebP
- 动图类：GIF、APNG、**动图 WebP**
- 矢量类：SVG
- 图标类：ICO

### 导出（处理完成后另存）

- 位图类：JPEG、PNG、BMP
- 图标类：ICO

> **v0.2 变更**：**WebP 已从导出列表移除**。`image 4.12.0` 仅提供 `webp_decoder.dart`，无任何编码器实现，纯 Dart 链路无法产出 WebP。WebP 作为导入格式完整保留（解码 → 转 PNG/JPEG 导出）。原「四.2 / 四.5 / 五.3」中 WebP 导出相关承诺同步作废，见附录 #13。

> 边界约定：
>
> 1. **SVG**：**仅渲染为位图导出，不支持矢量源码编辑、不支持导出 SVG 矢量文件**；**光栅化尺寸在导入时选择**（附录 #4 已拍板）：默认按 viewBox 推断（无 viewBox 则长边 1024），可选预设 512/1024/2048 或自定义宽高。
>    **v0.2 补充**：光栅化完成后的位图即为该次编辑会话的「原图」，二.3 的目标像素钳制上限、三.1 的 upscale 倍率均以此为基准。光栅化依赖 Flutter Engine（非纯 Dart），见七.2 例外条款与十二 ADR-004。
> 2. **APNG / GIF / 动图 WebP**：MVP 阶段仅加载预览；裁剪/变换后默认导出**静态位图**。动图帧编辑、重新导出动图标记为高阶可选（附录 #3 已拍板：动图 WebP 同 GIF/APNG 边界处理）。
>    **v0.2 补充（原缺失，必须明确）**：
>    - **导出取帧规则**：默认取第 1 帧；若用户在预览中手动翻过帧，取用户停留的当前帧；导出确认面板需显示「将导出第 N 帧，共 M 帧」。
>    - **解码帧数上限**：`总帧数 × 单帧像素 ≤ 2 亿` 且 `帧数 ≤ 200`，超限只解前 N 帧用于预览并提示「动图过大，仅预览前 N 帧，导出的静态帧不受影响」。
>    - **动图预览策略**：预览仅解码并循环播放前 50 帧；九.3 的预览降采样对动图按**每帧独立降采样**执行。
> 3. TIFF、TGA、PPM：小众格式，已移出 MVP（全端不支持），移入需求池六.10，有真实需求再拉回（附录 #8 已拍板）。
> 4. **ICO**：多尺寸容器格式，导出 UI 已定（附录 #2 已拍板）：默认勾选 16/32/48/64/128/256 全套、可取消勾选（至少保留一个），打包为单文件。
>    **v0.2 补充 3 条硬约束**（`ico_encoder.dart` 实测：内嵌 PNG 数据，`WinEncoder.encodeImages()` 对 `width > 256 || height > 256` 直接抛异常）：
>    - **尺寸上限 256**：目标尺寸超过 256 的选项在 UI 中不出现（当前默认值 256 已是库上限，无余量）。
>    - **放大置灰**：`目标尺寸 > 原图对应边` 的勾选项自动取消并置灰，附文案「原图小于该尺寸，无法生成」。禁止用 upscale 生成小图标的放大版本。
>    - **逐尺寸重采样**：ICO 打包时每个尺寸独立缩放，算法按尺寸自动选择（<64px 用 nearest + area，≥64px 用 lanczos），不沿用用户在页面顶部选定的算法。
> 5. **格式探测以文件内容为准（magic bytes），扩展名仅作提示**（v0.2 新增，原缺失）：

    | 格式 | 魔数 / 判定规则 |
    |------|----------------|
    | JPEG | `FF D8 FF` |
    | PNG | `89 50 4E 47 0D 0A 1A 0A`；再扫描 `acTL` chunk，存在则为 **APNG** |
    | GIF | `47 49 46 38`（`GIF8`） |
    | WebP | `52 49 46 46` + 偏移 8 处 `57 45 42 50`（`RIFF`…`WEBP`）；含 `VP8X` 且 flags 带 `ANIM` 位则为**动图 WebP** |
    | BMP | `42 4D` |
    | ICO | `00 00 01 00` |
    | SVG | 去 BOM 与空白后以 `<svg` 开头，或 XML 序言后首个元素为 `<svg` |

    - 扩展名与内容不一致：**以内容为准**，导入后 toast 提示一次「文件扩展名为 .jpg，实际内容为 PNG，已按 PNG 处理」。
    - 内容无法识别但扩展名在支持列表内：按「文件损坏/不支持」走九.2 错误卡片（错误码 `E-IMG-002`）。
    - **禁止**用扩展名单独判定 APNG 与 PNG（二者同为 `.png`，靠扩展名判断必然把动图当静态图并静默丢帧）。

## 二、裁剪功能

1. **载入与视图**：载入原图，画布视图自动缩放适配，**视图尺寸无需等于原图像素尺寸**；支持手势/鼠标平移、缩放浏览原图。
2. **选区形状**：正方形选区、圆形选区；**常用比例预设**（1:1、4:3、3:2、16:9）+ 自由拖拽选区 + 比例锁定。
   **v0.2 补充：形状 × 比例合法性矩阵**（原缺失，「圆形选区 + 16:9 预设」此前无定义）：

   | 形状 | 自由拖拽 | 1:1 | 4:3 | 3:2 | 16:9 |
   |------|---------|-----|-----|-----|------|
   | 矩形 | ✅ | ✅ | ✅ | ✅ | ✅ |
   | 圆形 | ✅（强制正方形） | ✅ | ❌ 置灰 | ❌ 置灰 | ❌ 置灰 |

   圆形选区本质是正方形选区 + 圆形遮罩，非 1:1 比例下列选择灰并提示「圆形选区仅支持 1:1」。「正方形选区」与「1:1 预设」为同一能力，UI 只保留一处入口（比例预设），不重复出现。
3. **手动指定选区目标像素尺寸**（例：1200×1200）：
   - 输入的目标尺寸指**原图像素尺寸**，在原图上框选对应区域。
   - 界面按当前缩放比例渲染选区框：例：原图 2400×2400 在界面显示为 200×200（缩放比 1/12）时，输入 1200×1200，屏幕上绘制的选区框实际为约 100×100。
   - **钳制规则**：输入框钳制上限为原图对应边尺寸（原图 800×800 时无法输入 1200）；拖拽选区超出图片边界时，选区自动吸附钳制到图片边界。SVG 源以光栅化后的位图尺寸为「原图尺寸」。
   - **初始定位规则（v0.2 新增，原缺失）**：输入目标尺寸后，选区以**当前选区中心为锚点**重新生成；若无选区则以**原图中心**为锚点；任一边越界时整体向内平移至贴合边界。输入即锁定选区尺寸，用户此后只有平移自由度。圆形选区时输入值为外接正方形边长。
4. **像素对齐与坐标显示**：
   - 选区坐标**吸附到整数像素**，杜绝小数像素选区导致的导出尺寸 1px 误差。
   - 界面实时显示选区对应的**原图坐标（x, y）与尺寸（宽×高）**，不受视图缩放影响。
5. **选区与视图联动**：选区定义在**原图坐标系**；视图缩放/平移仅影响显示，选区框必须跟随视图变换同步渲染，**不允许出现选区"漂移"**。
6. **透明通道**：导出 PNG 时，完整保留原图透明通道。
7. **圆形选区导出规则**：输出方形画布，圆形区域保留图像，圆形以外区域填充透明；不存在真正意义上"圆形的图片文件"，界面提示。
   **v0.2 补充**：画布边长 = 选区边长（圆形选区必为正方形）；圆形边界**启用抗锯齿**（否则边缘锯齿不可用），因此边缘 1px 过渡带内的 alpha 值会变化，验收标准见十一.1 的分项说明。

> 注：像素对齐的裁剪是**直接像素拷贝，不涉及重采样**；重采样算法选项见"三、尺寸与比例变换"。

## 三、尺寸与比例变换

1. 修改图片像素尺寸：自定义宽高；**允许放大（upscale）但有上限**——目标边长 ≤ 原图对应边 4 倍且总像素 ≤ 4000 万，超限输入框钳制并提示。SVG 源同规则，基准为光栅化后尺寸。
2. 修改图片比例，提供 3 种变换模式：
   - 拉伸填充：不保持原图比例，强制拉伸填满目标尺寸
   - 保持比例裁剪（居中裁切，cover）
   - 保持比例留白填充（contain）：空白区域填充底色（支持透明底色、自定义纯色）
3. **重采样算法**：缩放/比例变换时可选重采样算法（基础版默认高质量 **Lanczos**，进阶可加选项：双线性、最近邻等）。
   **v0.2 补充**：算法选择仅作用于「尺寸与比例变换」主操作与「转 ICO」的 ≥64px 尺寸；ICO 的小尺寸走一.4 的自动规则，不受此处影响。

## 四、格式转换

> **v0.2 结构变更**：**本章与第五章共用同一个「导出面板」**。用户在导出面板上同屏完成「选格式 + 调质量」一次编码，不再走「先转换、再压缩」两次有损流程。首页「格式转换」与「图片压缩」两个入口指向同一页面，仅默认聚焦的 Tab 不同。章节编号保留以维持既有引用。

### 4.1 转换矩阵（N×M，v0.2 新增；原文字描述改为表格）

| 源 ↓ / 目标 → | JPEG | PNG | BMP | ICO |
|--------------|------|-----|-----|-----|
| JPEG | ✅ 重编码 | ✅ | ✅ | ✅ 缩至 ≤256 |
| PNG | ⚠️ 透明填底 | ✅ 保留 alpha | ⚠️ 丢透明，需提示 | ✅ 缩至 ≤256 |
| BMP | ✅ | ✅ | ✅ | ✅ 缩至 ≤256 |
| WebP | ⚠️ 透明填底 | ✅ 保留 alpha | ⚠️ 丢透明，需提示 | ✅ 缩至 ≤256 |
| GIF | ✅ 取指定帧 | ✅ 取指定帧 | ⚠️ 丢透明 | ✅ 取指定帧 |
| APNG | ✅ 取指定帧 | ✅ 取指定帧 | ⚠️ 丢透明 | ✅ 取指定帧 |
| SVG | ✅ 先光栅化 | ✅ 先光栅化 | ✅ 先光栅化 | ✅ 先光栅化 |
| ICO | ✅ 取最大尺寸帧 | ✅ 取最大尺寸帧 | ✅ | ✅ 重新打包 |

> ⚠️ = 需界面提示；❌ 项（WebP 作为目标）已整体移除。
> 「取最大尺寸帧」：ICO 源含多尺寸时，默认取像素数最大的那一份作为位图源。

### 4.2 透明通道保留

PNG → PNG、PNG → ICO：保留透明通道。
**WebP → PNG** 同样保留 alpha（v0.2 补，原缺失）。凡目标格式不支持 alpha，均按九.4「透明填底色」处理并提示。

### 4.3 JPG 转出

JPG 本身无透明信息，仅封装转换。

### 4.4 PNG 转 JPG

透明区域自动填充底色，界面强提示：**JPG 不支持透明通道，透明区域将丢失**。

### 4.5 WebP（v0.2 变更）

- **导入支持**：WebP 可正常导入、预览、参与裁剪/尺寸变换/压缩参数预览。
- **导出不支持**：导出面板中 WebP 选项**不出现**（非置灰，直接不渲染），页脚固定说明「受纯 Dart 解码库能力限制，本版本不支持导出 WebP」。
- **源格式降级提示**：用户导入 WebP 后导出时，默认格式回退为 PNG，**必须显式提示**「WebP 暂不支持导出，已改为 PNG（体积可能增大）」，不得静默切换。

### 4.6 BMP 注意事项（v0.2 新增）

BMP 技术上可通过 32bpp + BITMAPV5 头写入 alpha，但 Windows 照片查看器、主流浏览器、微信均**忽略** BMP 的 alpha 通道，透明区域显示为黑或白。因此：

- 导出 BMP 时若源图含透明，按九.4 处理（默认填白底）并提示，**不支持「透明底色 + BMP」组合**（原九.4 表述有误，已修正）。
- 界面文案避免出现「BMP 支持透明」。

### 4.7 导出前体积预估（v0.2 新增）

导出面板实时显示预估输出体积与压缩率（相对源文件）。实现方式：对降采样至长边 512 的临时图快速编码，按像素数外推，debounce 300ms。仅在预估误差可能超过 30% 时（如小体积高压缩比场景）标注「预估」。

## 五、图片压缩

> 本章与第四章共用导出面板，见章首说明。

1. **JPG 压缩**：可调节质量参数（1–100），有损压缩。
   **v0.2 补充**：增加「渐进式」开关（默认关，开启利于网页渐进加载）与「色度抽样」选项（4:2:0 默认 / 4:4:4 高质量）。二者均为 `image` 包 `JpegEncoder` 原生能力，几乎零成本，属 MVP 范围。
2. **PNG 压缩**：支持有损调色板压缩 / 无损压缩二选一；**检测到半透明像素（0<alpha<255）时自动禁用调色板选项并说明原因**，防止 PNG8 将半透明压成二值透明（附录 #1 已拍板）。
3. **WebP 压缩**：**本节随 WebP 导出能力一并暂缓（附录 #13）**。导出面板无 WebP 目标，压缩参数区不出现 WebP 质量滑块。若后续引入 FFI 方案恢复导出，本节随之启用。
4. **体积预估**：见四.7。
5. **边界**：BMP 默认无压缩；ICO、SVG 不做压缩功能。
6. **一次编码原则（v0.2 新增）**：任一导出操作只允许经过一次有损编码。禁止「先转格式再压缩」的两段式实现，转换与压缩参数必须在同一次编码调用中同时生效。

## 六、文件交互

### 6.1 导入方式

- Windows：文件选择器 + 拖拽导入（拖拽时按扩展名预过滤，落地后仍按一.5 内容探测校验）
- Android / HarmonyOS Next：系统文件选择器（Android 13+ 走 **Photo Picker 免权限方案**，低版本回退传统选择器）
- Web：文件选择 + 粘贴图片
- 微信小程序：从相册选择

### 6.2 导出通道矩阵（v0.2 重写；原文「唤起系统保存面板」在移动端不成立）

> **背景**：Android / 鸿蒙不存在「系统保存对话框」这一概念。`file_selector` 仅 Windows 实现 `getSaveLocation`，移动端无对应 API。必须按端定义具体通道，否则移动端导出的实现会在开发中期才暴露。

| 端 | 导入实现 | 导出实现 | 备注 |
|----|---------|---------|------|
| Windows | `file_selector.openFile` + 拖拽 | `file_selector.getSaveLocation` → 写文件 | 系统面板自带同名冲突处理 |
| Android | `file_selector.openFile`（13+ Photo Picker） | **待定**，候选：① `flutter_file_dialog`（SAF `ACTION_CREATE_DOCUMENT`）② MediaStore（需权限）③ 写临时目录 + `share_plus` | 见附录 #14，**开发启动前必须拍板** |
| HarmonyOS Next | `file_selector` ohos 变体（需核对适配清单） | 同上，取 `_ohos` 变体 | 插件可用性风险最高，见七.2 |
| Web | `<input type="file">` / paste | Blob + `<a download>` | 不走 File System Access（附录 #10） |
| 微信小程序 | `wx.chooseMedia` | `wx.saveImageToPhotosAlbum` | V3+ |

- 移动端覆盖同名文件前弹确认。
- 导出目录不可写、磁盘空间不足、权限被拒均按九.2 错误码处理，提供「换一个位置」或「重试」。

### 6.3 权限适配

移动端优先 Photo Picker 免权限路线（Android 13+ / 鸿蒙对应方案），仅低版本回退传统存储权限；无网络上传动作。

### 6.4 单张约束

MVP 一次只处理一张图片，所有导入入口均为单选；批量处理见需求池三。

### 6.5 导入失败兜底（v0.2 新增）

- 拖拽多文件时只取第一个并提示「当前版本一次只处理一张图片」。
- 拖入非图片文件：不进入解码，直接 toast「不支持的文件类型」，停留在当前页。
- 导入过程中取消：回到空态，不残留半解码状态。

## 八、非功能需求

1. **离线优先**：所有图片解码、编辑、压缩、转换运算全部在本地运行，不请求后端上传原图。
2. **透明通道一致性**：凡是目标格式支持 Alpha 通道的，必须保证处理链路不丢失透明。
3. **内存控制**：大图（4K+、大尺寸 GIF）做采样预览，避免 OOM；移动端严格管控内存。量化阈值见九.3。
4. **性能**：裁剪、转换、压缩过程展示加载进度；**MVP 不做任务取消**（`image` 包编码不支持中断，协作式真取消移入需求池六.11，附录 #9 已拍板）。
5. **无水印**：工具本身导出图片不会自动增加额外水印。

6. **EXIF / 元数据（v0.2 重写；原「剥离全部元数据」会把色彩和 DPI 一起弄坏）**

   元数据分两类，处理策略不同：

   | 类别 | 内容 | 导出策略 |
   |------|------|---------|
   | **隐私类** | EXIF（GPS、拍摄时间、设备型号、序列号、镜头信息）、XMP、IPTC、MakerNote | **默认剥离**，定位为隐私特性并在界面注明「已移除拍摄地点与设备信息」 |
   | **渲染类** | ICC Profile（iCCP）、pHYs（DPI）、gAMA、sRGB chunk | **必须保留**，见下 |

   - 源图色彩空间非 sRGB（如 Display P3、Adobe RGB）：导出前转为 sRGB，并写入 sRGB ICC profile。目标格式不支持 ICC（BMP）时仅做像素值转换，不写 profile。
   - 源图含 pHYs：保留原始 DPI 值；无 pHYs 时不写入（不臆造 72 DPI）。
   - `image` 包 `PngEncoder` 原生支持 `_writeICCPChunk()` 与 `pixelDimensions` 参数，保留渲染类元数据零额外成本。
   - 显示与处理前应用 EXIF orientation（附录 #6 已拍板：MVP 必做）：解码后立即 `bakeOrientation`，旋转视为已烧入像素，**不得二次旋转**。

7. **反悔兜底（v0.2 变更）**：MVP 只提供「**重置 / 重新载入原图**」（回到本次会话的初始载入状态，含恢复全部参数默认值）。
   **「单步撤销」移入需求池六.8**：在「独立单任务」模型下，单页内只有一个可变参数，撤销语义与重置高度重叠；而实现需缓存一份位图快照，移动端峰值内存直接翻倍，收益远低于成本。

8. **色深与色彩管理**（附录 #12 已拍板）：解码失败（如 CMYK JPEG）→ 按九.2 错误卡片提示「不支持该编码」（`E-IMG-003`）；可解码但降级（如 16-bit PNG 降 8-bit）→ 导入后 toast 提示一次，可继续。

9. **执行线程约束（v0.2 新增，原缺失）**

   所有解码、重采样、编码操作**必须在后台 Isolate 中执行**，主 Isolate 只负责 UI 与进度回传：

   - Windows / Android / 鸿蒙：`Isolate.run()` 或 `compute()`；大图数据进出 Isolate 使用 `TransferableTypedData` 避免内存拷贝翻倍。
   - **Web 例外**：Flutter Web 的 `compute()` 无真线程，等于主线程同步执行。Web 端必须依赖九.3 的更低像素上限来规避冻结，或评估 Web Worker 方案（不在 MVP）。
   - 进度回传采用节流（≤10 次/秒），避免消息风暴。
   - 移动端编码任务串行执行，禁止并发大图任务。

### 9.1 编辑会话模型（已拍板，v0.2 微调）

### 9.3 内存阈值（八.3 的量化）—— **v0.2 重写**

**（1）延迟渲染架构（原「既要降采样又要保留全分辨率」自相矛盾，此处定死）**

```
导入 → 解码全图 → 生成长边 ≤2048 的预览图 → 立即释放全图
     → 编辑仅操作预览图 + 参数（选区/目标尺寸均记录在「原图坐标系」）
     → 导出时：从源文件字节流重新解码全图 → 应用参数 → 编码 → 释放
```

- 编辑态只保有一份预览图（长边 ≤2048，约 16MB），参数以原图坐标系存储，缩放前后一致。
- 导出期峰值 = 全尺寸图 + 编码输出缓冲，**不含预览图**（预览图在导出开始时释放）。
- 二次解码使导出耗时增加约 40%–100%，导出进度条必须覆盖「重新解码 → 处理 → 编码」三段，文案分别为「载入原图 / 处理中 / 写入文件」。
- 源文件字节流在会话期内缓存（不重复读盘），但**不缓存已解码位图**。

**（2）分端处理上限（原统一 100MP 对移动端必 OOM）**

| 端 | 像素上限 | 依据 |
|----|---------|------|
| Windows | **100 MP** | 400MB 位图，桌面内存充足 |
| Android / HarmonyOS Next | **32 MP** | 128MB 位图，中端机 heap 512MB 留 3× 余量 |
| Web（桌面浏览器） | **50 MP** | Chrome 可承受 |
| Web（移动浏览器） | **16 MP** | iOS Safari 画布与内存限制远严于 Chrome，附录 #15 待实测确认 |

- 超限直接拒绝（`E-IMG-004`），不做降级处理——降级会让用户拿到与原图不符的结果。
- 预检在解码前执行：仅读文件头取得宽高，不解码像素。`宽 × 高 × 4 + 编码缓冲估算` 与平台可用内存对比，不足则 `E-IMG-005`。
- **Dart 的 OOM 是进程级 crash，catch 不住**，因此九.2 的错误卡片只能依赖解码前预检拦截，不能依赖异常捕获兜底。

**（3）预览降采样**：原图边长 > 4096px 或总像素 > 2000 万时，预览图长边降至 2048；否则预览图 = 原图（省一次缩放）。
**（4）并发**：移动端编码任务串行执行，禁止并发大图任务。

### 9.5 页面状态机（v0.2 新增）

每个功能页共用同一套状态机，页面仅在「可编辑」态内容不同：

```

                          |

                          |

                          |

```

- 解码中/导出中都禁用所有输入控件，仅保留进度与取消关闭（关闭 = 丢弃本次结果）。

| 透明通道 | 半透明 PNG 样本经**矩形裁剪 / 改尺寸 / PNG→PNG 转换**后 alpha 值逐像素一致（**注：WebP 目标已移除，原条款作废**） |
| 透明通道（圆形选区） | 圆心区域 alpha 逐像素一致；**边缘 1px 过渡带允许抗锯齿差异**（原「逐像素一致」对圆形不成立，此处拆分） |
| EXIF orientation | 竖拍样本显示方向与导出方向一致，且不二次旋转 |
| 元数据 | 导出图不含 GPS/拍摄时间/设备型号；广色域样本导出后色彩偏移 ≤ ΔE 2.0；300 DPI 样本导出后 DPI 保持 |
| upscale 钳制 | 输入超限值被钳制到上限（4 倍边长 / 4000 万像素），不产生越界导出 |
| 圆形选区 | 输出为方形画布 + 圆外透明，界面有提示文案 |
| ICO 导出 | 勾选 N 个尺寸 → 输出单文件含 N 个图标项；每项尺寸与勾选值一致；超出原图尺寸的选项被置灰 |
| 格式探测 | 将 PNG 改名为 `.jpg` 导入 → 按 PNG 处理并提示；APNG 导入 → 识别为动图、帧数正确、不丢帧 |
| 错误边界 | 损坏文件 / 超限文件按九.2 与错误码表给出对应提示，不崩溃 |
| 反悔兜底 | 重置后所有参数回到默认值、预览回到初始载入状态 |
| 体积预估 | 预估体积与实际导出体积偏差 ≤ 30%（20 组样本，排除 <50KB 小文件） |

## 十二、架构决策记录（ADR，v0.2 新增）

> 以下 5 条为本次评审后拍板的重大决策，后续开发不得静默推翻；如需变更须新增 ADR 条目并回写相关章节。

### ADR-001：不支持导出 WebP，仅保留导入

- **决策**：MVP 及可见版本内不做 WebP 导出。
- **依据**：`image 4.12.0/lib/src/formats/` 仅有 `webp_decoder.dart`，全库无 `WebPEncoder` 类；纯 Dart 生态无可用编码器。
- **被否方案**：① FFI 引入 libwebp——破纯 Dart 铁律，Windows/Android/鸿蒙三端各需编 native 库，鸿蒙风险极高；② 自研 VP8L 编码器——半年起步，不建议。
- **影响**：一（导出列表）、四.5、五.3、九.4、十、十一.1 已同步修订；WebP 源导出需显式提示降级为 PNG。
- **重开条件**：出现成熟的纯 Dart WebP 编码包，或鸿蒙 native 构建链路成熟到可承受 FFI。

### ADR-002：采用「延迟渲染」内存架构

- **决策**：编辑态只持有长边 ≤2048 预览图，导出时从源文件二次解码全图。
- **依据**：原「降采样预览 + 全分辨率导出」自相矛盾——保留全图则降采样无意义，丢弃全图则必须二次解码。
- **代价**：导出耗时增加 40%–100%；进度条需覆盖三段。
- **备选**：始终持有全图——32MP 需 128MB，移动端多任务场景易被系统回收，且无法支撑 100MP 桌面场景。

### ADR-003：编解码在后台 Isolate 执行

- **决策**：所有解码/重采样/编码走 `Isolate.run()`；Web 端为已知例外，靠低上限规避。
- **依据**：主线程解码会冻结 UI，进度条本身也会卡死。
- **注意**：跨 Isolate 传大图须用 `TransferableTypedData`，否则内存翻倍。

### ADR-004：SVG 光栅化为纯 Dart 铁律的唯一例外

- **决策**：允许 `flutter_svg` + `PictureRecorder` 参与 SVG 光栅化。
- **依据**：`image` 包无 SVG 解码器，无纯 Dart 替代。
- **影响**：SVG 无法在单元测试覆盖；Web 端 SVG 延迟放行（七.4）。

### ADR-005：元数据分级剥离

- **决策**：剥隐私类（EXIF/GPS/XMP/IPTC），留渲染类（ICC/pHYs/gAMA/sRGB）。
- **依据**：全剥会导致 P3 照片偏色、打印 DPI 错乱，且与八.8 色彩管理自相矛盾。
- **代价**：需实现非 sRGB → sRGB 的像素转换（`image` 包有 `ColorProfile` 基础能力，需验证）。

## 十三、页面清单与导航结构（v0.2 新增）

> 原文档通篇只有功能描述，没有「有哪些页面」，开发时无法直接拆任务。

```
像素工坊
├── 首页 /
│   ├── 导入卡（选择文件 / 拖拽区 / 粘贴提示，按端渲染）
│   └── 功能入口（4 个入口 → 3 个页面）
│       ├── 裁剪              → /crop
│       ├── 尺寸与比例         → /resize
│       ├── 格式转换           → /export?tab=convert
│       └── 图片压缩           → /export?tab=compress
├── /crop        裁剪页
├── /resize      尺寸与比例页
├── /export      导出面板（格式转换与压缩合并；`tab` 参数决定默认分区）
└── 全局
    ├── 错误卡片（页内组件，非独立路由）
    ├── 关于页（版本号 / 开源许可 / 隐私说明 / 导出诊断日志）→ /about
    └── 设置（主题、语言，P1）
```

> **入口数量说明**：首页保留「格式转换」与「图片压缩」两个独立入口（符合用户对工具集的直觉，也避免「只想压一下图」的人多绕一步），但两者指向同一 `/export` 页面，仅默认 Tab 不同。因此是 **4 个入口 / 3 个页面**。

**导航规则**：

- 首页 → 功能页为 `push`，功能页返回首页保持首页状态（导入的缩略信息保留）。
- 功能页之间**无横向跳转**（九.1 独立单任务）。
- 未选图时进入功能页：直接展示空态 + 导入按钮，不自动唤起文件选择器（避免用户误触后被困在系统选择器）。
- 导出完成不为独立页面，用 `Dialog` 呈现，含「打开所在文件夹」（Windows）/「分享」（移动端）/「完成」。

**v0.2 代码适配（已完成）**：路由已由 `crop / resize / convert / compress` 四条合并为 `crop / resize / export` 三条，`/export` 通过 `?tab=convert|compress` 决定默认分区；`features/convert`、`features/compress` 已删除，合并为 `features/export/export_page.dart`；首页 4 个入口指向 3 个页面；`test/widget_test.dart` 已补两个入口的导航用例。

## 十四、性能预算（v0.2 新增）

见十一.2 的具体数值表。补充约束：

1. **启动预算**：首帧 ≤ 800ms（Windows）/ 1.5s（移动端）；首页不预加载任何图片库资源，`image` 包按需 import，避免拖慢冷启动。
2. **包体预算**：Windows ≤ 40MB、Android ≤ 25MB、鸿蒙 ≤ 25MB、Web 首屏 ≤ 5MB（gzip 后）。超预算时优先砍 SVG 光栅化（`flutter_svg` 体积较大）而不是砍功能。
3. **内存预算**：见十一.2；移动端以「系统不触发 LMK 回收」为红线，预检时必须查询可用内存而非固定阈值。
4. **无卡顿红线**：任何用户操作后 100ms 内必须有视觉反馈（哪怕只是 loading 态）。
5. **测量方式**：Windows 用 DevTools Memory + 手工计时；Android 用 `dumpsys meminfo` + Android Studio Profiler；鸿蒙用 DevEco Profiler。数据记入验收报告。

# 需求池（扩展待开发需求，不分优先级，包含【可选小功能】+【范围外高阶需求】）

> 使用说明：MVP 版本先不纳入，后续迭代按需挑选；同样遵守多端差异化，不支持的端直接隐藏

## 一、图文装饰类

1. 文字水印：支持自定义文字内容、字体、字号、颜色、透明度、旋转；支持铺满重复水印/单点水印；支持选择放在四角、居中
2. 图片水印：导入本地图片作为水印，可调整大小、透明度、旋转、位置；PNG 水印保留透明通道
3. 边框功能：纯色边框、圆角边框、虚线边框；可设置边框宽度、圆角大小；透明图片边框不破坏 alpha 通道
4. 底色填充：给图片增加背景色/渐变背景（线性渐变、径向渐变），支持透明底色
5. 形状遮罩：除圆形、方形外，增加椭圆、五角星、圆角矩形等遮罩裁剪
6. 阴影：给图片/裁剪图形增加外阴影，可调偏移、模糊、透明度

## 二、调色与基础像素调整类

1. 基础调色：亮度、对比度、饱和度、色相、锐化、降噪
2. 黑白化、反色（负片）
3. 色温、色调微调
4. 通道操作：单独调整 RGB 通道、Alpha 通道（透明通道）
5. 模糊：高斯模糊、径向模糊、马赛克打码（可框选区域打码）

## 三、批量处理类

1. 批量导入多张图片，统一执行：改尺寸、格式转换、压缩、加水印
2. 批量导出，支持自定义输出文件夹、统一命名规则（序号前缀）
3. 批量任务队列：支持暂停、取消、查看失败项
4. **按目标体积压缩**（v0.2 新增）：指定「压到 ≤ N KB」，二分搜索质量参数逼近目标。压缩类工具的高频刚需，待批量能力一起做更有价值

## 四、画布与排版类

1. 画布扩展：在原图四周扩展画布（放大画布，原图不动），扩展区域填充透明/纯色/渐变
2. 图片拼接：横向拼接、纵向拼接，支持设置图片之间间距、背景
3. 九宫格切图：一张图均等切分为多张小图
4. 翻转旋转：90°/180° 旋转、水平翻转、垂直翻转

## 五、信息与辅助类

1. 图片信息查看：读取并展示宽高、文件大小、格式、色深、是否带 Alpha、DPI、EXIF 信息
2. EXIF 操作：查看 EXIF；可选清除 EXIF 隐私信息（位置、拍摄时间、设备信息）
3. 色值拾取：取色器，点击画布获取 RGBA/HEX 色值
4. 网格/参考线：编辑画布显示辅助网格、自定义参考线，方便对齐
5. 预设模板：常用尺寸预设（头像尺寸、小红书封面、公众号配图、图标尺寸），一键套用
   **v0.2 建议提前至 P1**：纯数据配置、成本几小时，对中文用户价值极高，可随 M1 一起交付

## 六、高阶/重功能（成本高，放在池子里，谨慎排期）

1. GIF/APNG 帧编辑：帧预览、单帧修改、删帧、调整帧延时、导出新动图
2. 颜色量化：调色板减少颜色，用于大幅减小 PNG/GIF 体积

4. 图片合并图层（多层图片叠加，上层支持透明）
5. 简单滤镜预设（复古、冷调、胶片等）

7. 剪贴板快捷操作：复制图片到剪贴板、从剪贴板粘贴图片

## ✅ 已结案：#13 image 包 WebP/ICO 编码能力

**原问题**：image 4.x 疑似仅支持解码、不支持编码，与「导出支持」承诺冲突。

**实测结论（`image 4.12.0` 源码级核查）**：

| 能力 | 证据 | 结论 |
|------|------|------|
| WebP 编码 | `formats/` 下仅 `webp_decoder.dart`；`webp/` 目录 14 个文件全为解码（vp8/vp8l/alpha/frame）；全库检索 `WebPEncoder` 零命中 | ❌ **不可编码** |
| WebP 解码 | `webp_decoder.dart` 存在，支持动图帧 | ✅ 可解码 |
| ICO 编码 | `ico_encoder.dart` → `WinEncoder.encodeImages()`，内嵌 `PngEncoder` 输出；`width>256 \|\| height>256` 抛异常 | ✅ **可编码，限 ≤256** |
| PNG 调色板 | `png_encoder.dart` 支持 `hasPalette` + 写 PLTE；`filter/quantize.dart` 存在 | ✅ 可实现 |
| SVG 解码 | 无任何 svg 解码器 | ❌ 需 Flutter Engine（ADR-004） |

**处理**：WebP 导出全端移除（ADR-001）；ICO 导出确认为可用并补 3 条硬约束（一.4）；一/四/五/七/九/十/十一章已同步修订。
